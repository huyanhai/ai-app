# 画布拖拽与平移性能优化设计

## 目标

减少节点较多时拖拽节点和平移画布的主线程开销，不改变画布交互、节点内容和历史记录行为。

## 已确认瓶颈

- 节点或连线每次变化都会生成新快照，并对前后两份完整快照执行 `JSON.stringify` 比较。拖拽节点会高频触发该过程，数据量随节点和媒体内容增长。
- 图片节点通过 `useViewport` 订阅完整视口。平移改变视口坐标时，所有图片节点都会重渲染，但节点仅在编辑标记的反向缩放中使用缩放值。

## 优化方案

### 快照比较

- 在 `frontend/app/pipeline/page.tsx` 中用快照引用比较替代两次完整 JSON 序列化。
- 保留现有快照生成、500ms 历史合并、600ms 防抖保存、撤销和重做逻辑。
- 依赖现有节点与连线的不可变更新方式；未发生状态变化时复用当前快照引用。

### 视口订阅

- 在 `frontend/components/pipeline/nodes/node/image/index.tsx` 中仅订阅视口的缩放值，不再订阅平移坐标。
- 保留图片标记、删除按钮和缩放手柄现有的反向缩放效果。
- 不修改图片编辑器的独立视口逻辑。

## 不在本次范围

- 不启用 `onlyRenderVisibleElements`，避免离屏节点卸载导致编辑器或草稿等本地状态丢失。
- 不增加拖拽简版节点、交互降级渲染或新的状态管理抽象。
- 不调整画布功能、布局、样式和后端接口。

## 验证

- 运行前端 lint 和构建，确认类型与依赖使用正确。
- 在多节点画布中连续拖拽节点，确认移动跟手，连续拖拽仍合并为一个历史步骤。
- 平移和缩放画布，确认节点内容、选中态与连线正常。
- 编辑带标记的图片，确认标记、删除按钮和缩放手柄在缩放后保持原有尺寸与行为。
- 验证撤销、重做和刷新后的自动保存恢复不受影响。
