# 导演智能体自动制作方案设计

## 目标

用户输入一条创意后，导演智能体依次完成剧本、角色和分镜规划，并在画布上创建可编辑的节点工作流。每个文本阶段经用户确认后才进入下一阶段。分镜确认后，系统按依赖生成角色参考图、场景参考图、分镜图和视频。

第一版采用“分阶段规划、逐阶段确认”的交互方式。文本规划阶段不得调用图片或视频生成服务。

## 方案选择

采用“导演智能体 + 后端工作流工具”。智能体负责理解创意、生成结构化规划和响应修改；后端负责画布变更、任务调度、状态持久化和失败恢复。

采用后端阶段状态机，避免智能体自由对话跳步。不让前端或模型直接操作 React Flow 数据，避免画布状态与执行状态不一致。创作分工参考 OiiOii 公开的专业 Agent 流程，各角色共享同一份制作规划。

## 用户流程

1. 用户输入创意，可选填目标时长、视觉风格和画幅。
2. 编剧 Agent 只生成故事和场景剧本，会话框展示完整结果；用户确认或提出修改。
3. 剧本确认后，角色设计师生成角色设定；用户确认后才继续。
4. 角色确认后，场景师和分镜师生成场景与分镜；用户确认后才进入媒体阶段。
5. 用户选择自动或手动媒体模式。自动模式连续执行角色与场景参考图、分镜图、视频；手动模式由用户逐阶段启动。
6. 用户可暂停后续调度、重试失败节点或修改上游内容。

会话框按“编剧、角色设计师、场景师、分镜师、动画师”展示实际执行日志、阶段状态和结果卡片。每个文本结果卡片提供确认和修改入口。日志只记录可验证的工具调用和状态，不展示模型内部推理。

用户创意和各 Agent 卡片按时间顺序位于同一个滚动会话中，不使用底部独立状态面板。Agent 卡片包含头像、角色名称、执行耗时、折叠入口、自然语言执行说明和阶段结果。图片等媒体结果使用资源卡片展示。

当前待确认卡片底部提供全宽“确认并继续”和“我想修改”按钮。修改操作聚焦会话输入框，用户提交意见后由当前 Agent 重新生成。自动或手动媒体模式在分镜结果卡片内选择。欢迎创作模式区在会话开始后立即隐藏。普通会话与创作会话使用一致的消息布局。

## 阶段状态机

项目依次经过 `script_pending`、`script_review`、`characters_pending`、`characters_review`、`storyboard_pending`、`storyboard_review`、`media_ready` 和 `media_running`。

- `*_pending` 表示对应 Agent 正在执行，不能重复提交或提前确认。
- `*_review` 表示结果已生成，等待用户确认或修改。
- 只有确认当前文本阶段才能启动下一阶段，接口必须校验状态，不能依赖前端禁用按钮。
- 修改已确认阶段后回到对应 `*_pending`，并将后续阶段及受影响媒体标记为待更新。
- 分镜确认后保存 `auto` 或 `manual` 媒体模式。手动模式按参考图、分镜图、视频三个阶段提供执行按钮。

## 规划数据

后端以 `ProductionPlan` 作为制作规划的权威数据，包含：

- 项目设置：创意、目标时长、视觉风格和画幅。
- 故事：标题、梗概和完整故事。
- 场景：稳定的 `sceneId`、场景剧本、时间和地点。
- 角色：稳定的 `characterId`、姓名、外貌、服装和性格。
- 分镜：稳定的 `shotId`、所属场景、出场角色、画面描述、动作、运镜和时长。

所有跨节点引用使用稳定 ID，不使用数组下标或节点标题。`ProductionPlan` 保存版本号，用于识别上游修改影响的下游内容。

## 画布映射

| 规划内容 | 现有节点 | 主要内容 |
| --- | --- | --- |
| 故事和场景剧本 | 文本节点 | 可编辑文本 |
| 角色 | 主体节点 | 名称和一致性描述 |
| 场景与分镜描述 | 文本节点 | 可拍摄的视觉描述 |
| 角色、场景和分镜画面 | 图片节点 | 提示词、参考图和生成结果 |
| 镜头视频 | 视频节点 | 首帧、运动提示词、时长和生成结果 |

主要连接关系为：

`故事 → 场景剧本 → 分镜 → 分镜图 → 视频`

角色主体连接其参考图，并连接所有包含该角色的分镜图。场景参考图连接对应分镜图。分镜图作为视频节点的首帧；视频节点同时保留动作、运镜和时长配置。

后端根据规划确定性地创建节点和连线并自动布局。模型不生成坐标、React Flow 句柄或内部节点字段。

## 导演智能体工具

### `planCurrentStage`

根据当前阶段生成剧本、角色或分镜，结果仍写入统一的 `ProductionPlan`。修改已有规划时保留未受影响实体的稳定 ID。

### `confirmCurrentStage`

校验并确认当前文本阶段，再启动唯一合法的下一阶段。媒体确认同时记录自动或手动模式。

### `applyPlanToCanvas`

比较规划版本与现有节点映射，创建、更新或连接受影响节点。该工具由后端确定性执行，不调用生成模型决定图结构。

### `getProductionStatus`

返回规划版本、节点状态、任务进度和失败原因，供智能体回答进度问题。

### `startGeneration`

仅在用户明确确认后启动媒体生成。工具必须验证当前规划已确认，并拒绝在规划阶段直接生成媒体。

### `retryGeneration`

重试指定失败节点。重试前验证其上游依赖已完成，不影响无关节点。

## 执行与依赖

后端按以下阶段调度：

1. 角色参考图和场景参考图。
2. 依赖已完成的分镜图。
3. 依赖已完成分镜图的视频。

同阶段任务可并行执行，具体并发数由生成服务配置决定。单个任务失败时，仅阻止其下游任务，不阻塞无关镜头。

暂停操作停止领取新任务；已经开始的任务允许完成。服务重启或页面刷新后，后端根据持久化任务状态恢复进度。具有外部任务 ID 的视频任务先查询原任务，避免重复提交。

## 状态与修改

节点统一展示以下制作状态：

- `草稿`：已规划但未确认生成。
- `等待上游`：已确认，但依赖尚未完成。
- `生成中`：生成任务正在执行。
- `已完成`：结果可用。
- `失败`：任务失败，可查看原因并重试。
- `待更新`：上游规划已变化，当前结果不再对应最新版本。

修改场景或角色时，系统根据依赖图将受影响下游标记为“待更新”，不自动删除旧结果，也不立即产生新费用。用户再次确认后，仅重新生成待更新节点及其必要依赖。

## 持久化

后端保存 `ProductionPlan`、规划版本、节点与实体 ID 的映射、媒体任务状态、外部任务 ID 和失败原因。前端通过接口读取状态，不将智能体会话或 React Flow 快照作为唯一恢复依据。

## 第一版范围

包含：

- 剧本、角色、分镜逐阶段生成和确认。
- 会话框执行日志、结果卡片和阶段修改。
- 自动创建和连接画布节点。
- 自动或手动媒体生成模式。
- 暂停后续调度、单节点重试和断线恢复。
- 局部修改和下游失效标记。

不包含：

- 多集剧本和跨集角色管理。
- 自动配音、配乐和时间线精剪。
- 多人协作。
- 自动评估镜头质量或自动选择最佳图片。

## 验收标准

1. 输入创意后只生成剧本；未确认剧本时不调用角色、分镜或媒体生成。
2. 剧本和角色分别确认后才生成角色和分镜，会话框展示对应执行过程与结果。
3. 自动媒体模式按依赖连续生成；手动模式只在用户启动对应阶段后生成。
4. 单个任务失败不阻塞无关镜头，重试不会重复生成已成功节点。
5. 页面刷新或服务恢复后可继续查询和执行原任务，不重复提交已有外部任务 ID 的视频。
6. 修改场景或角色后，仅其受影响下游进入“待更新”，再次确认前不产生媒体费用。
7. 角色描述和参考图通过稳定 `characterId` 传递到所有相关分镜图。
