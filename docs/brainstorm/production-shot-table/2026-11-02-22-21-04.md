# 分镜表与独立提示词阶段

## 目标

严格按“剧本确认 → 角色确认 → 分镜确认 → 分镜图提示词 → 视频拍摄提示词 → 媒体执行”的顺序制作。整部剧只使用一个分镜 Table 节点集中展示所有镜头及两类提示词。

## 阶段流程

1. 编剧生成剧本，用户确认或修改。
2. 角色设计师生成角色，用户确认或修改。
3. 分镜师只设计镜头内容、动作、运镜、出场角色和时长，用户确认或修改；此阶段不生成媒体提示词。
4. 用户确认分镜并选择自动或手动媒体模式后，系统根据分镜自动补全分镜图提示词，不增加人工确认。
5. 系统结合剧本、已确认分镜和分镜图提示词自动生成视频拍摄提示词，不增加人工确认。
6. 两类提示词完成后进入媒体阶段；自动模式开始执行，手动模式等待用户逐阶段启动。

后端状态机增加分镜图提示词和视频提示词执行状态。原有 SSE 流式预览覆盖两个新阶段，完成结果继续通过结构化 Schema 校验。

## 单一分镜表节点

- 新增自定义 `shotTableNode`，每个制作项目只创建一个，包含全部场景和镜头。
- 表格行以稳定 `shotId` 标识；列包括镜号、场景、分镜内容、动作与运镜、时长、分镜图提示词、视频拍摄提示词。
- 分镜生成后表格立即出现；提示词生成前列显示待生成，流式阶段更新对应内容。
- 表格内容来自统一 `ProductionPlan`，不复制另一份可独立编辑的分镜数据。
- 删除原有每镜头文本节点，避免表格与文本节点重复展示。
- 角色、场景、分镜图和视频媒体节点继续保留，用于生成配置、依赖连接和结果展示；媒体不嵌入表格。

## 数据与执行

- 分镜 Schema 与媒体提示词 Schema 分离，镜头 ID 在提示词补全和修改时保持稳定。
- 分镜图提示词负责静态关键帧；视频提示词结合剧本语境描述动作、表演、运镜和镜头连续性。
- 图片节点读取分镜图提示词，视频节点读取视频拍摄提示词，现有依赖和失效检测继续有效。
- 修改已确认分镜后，两类提示词和受影响媒体标记为待更新，重新确认后才执行后续生成。

## 验证

- 未确认剧本、角色或分镜时不能运行后续阶段。
- 分镜确认后依次完成两类提示词，期间不调用媒体生成服务。
- 所有镜头只出现在一个表格节点中，图片与视频节点引用正确提示词。
- 制作流程测试、前后端构建和流式交互验证通过，测试不调用真实付费生成。
