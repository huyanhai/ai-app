# 制作规划流式进度

## 目标

剧本、角色、分镜及其修改请求执行期间，Agent 卡片实时显示模型输出预览和阶段状态；请求结束后仍使用现有结构化结果与用户确认流程，不自动越过确认边界。

## 方案

- 保留现有 JSON 接口，新增 `plan/stream`、`confirm-stage/stream`、`revise-stage/stream` 三个 POST SSE 接口。
- Planner 使用结构化输出流，将模型增量片段通过回调传给 Service；最终完整结果仍由 Zod 校验并写入项目。
- SSE 事件分为 `start`、`progress`、`chunk`、`result`、`error`。`start` 返回项目 ID，`chunk` 只用于当前页面预览，`result` 返回完整项目。
- Service 继续持久化开始、完成和失败事件，不把每个 token 写入数据库。

## 前端

- 使用 `fetch` 的 `ReadableStream` 解析 SSE，因为浏览器 `EventSource` 不支持 POST 请求体。
- Agent 卡片执行中展示实时文本预览、当前阶段和计时；完成后替换为正式结构化卡片。
- 正在生成时禁用重复确认和修改操作；网络错误保留已接收预览并显示错误，不伪造成功状态。
- 页面重新加载时通过项目 ID 获取已持久化状态，未完成的流式预览不要求恢复。

## 验证

- Planner 测试覆盖流式片段回调与最终结构化校验。
- Service 测试覆盖开始、增量、结果、失败事件及阶段确认边界。
- 前端构建、后端制作流程测试和构建全部通过；测试不调用真实付费模型。
